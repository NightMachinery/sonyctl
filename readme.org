#+title: sonyctl — Sony headphones CLI for macOS

Observe and change settings on Sony headphones (built and tested with the
WF-1000XM6 earbuds; should work with any "protocol v2" model, i.e. the
1000XM5 generation and newer) from the macOS command line.

macOS has no native UI for Sony's headphone settings and Sony ships no macOS
app. The headphones, however, speak Sony's proprietary MDR protocol over a
Bluetooth Classic RFCOMM channel that any paired host may use. =sonyctl= is a
thin CLI over [[https://github.com/mos9527/SonyHeadphonesClient][mos9527/SonyHeadphonesClient]]'s =libmdr= / =libmdr-bt=
libraries, which implement that protocol.

* Building

Requires macOS, CMake >= 3.31, and a C++20 compiler (Apple clang works).

#+begin_src sh
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
./build/sonyctl help
#+end_src

The build fetches the pinned upstream library source automatically
(FetchContent); the only third-party dependency it pulls is =fmt=.

** Install a prebuilt binary

Each tagged release publishes stripped macOS binaries — pick the one for your
Mac (=arm64= for Apple Silicon, =x86_64= for Intel; =universal= contains both
and is roughly twice the size):

#+begin_src sh
v=v0.1.0
curl -fLO "https://github.com/NightMachinery/sonyctl/releases/download/$v/sonyctl-macos-arm64"
xattr -d com.apple.quarantine sonyctl-macos-arm64   # downloaded binaries are unsigned
chmod +x sonyctl-macos-arm64
mv sonyctl-macos-arm64 ~/.local/bin/sonyctl
#+end_src

The binaries are not code-signed or notarized, so macOS quarantines them on
download; the =xattr= line above clears that. =SHA256SUMS.txt= is attached to
each release. Binaries require macOS 11 or newer.

Note there is no fully static option: macOS has no static libc and forbids
statically linking =libSystem=. All third-party code (libmdr, libmdr-bt, fmt)
*is* statically linked in, so the binaries depend only on Apple system
frameworks that ship with every Mac.

** Install from source

=install.sh= builds a Release binary and installs it to a local bin dir
(default =~/.local/bin=):

#+begin_src sh
./install.sh                 # -> ~/.local/bin/sonyctl
./install.sh /usr/local      # -> /usr/local/bin/sonyctl
PREFIX=~/opt ./install.sh    # -> ~/opt/bin/sonyctl
#+end_src

If the target bin dir is not on your =PATH=, the script prints the line to
add. Under the hood this is just =cmake --install=, so you can also run
=cmake --install build --prefix ~/.local= yourself.

* Usage

#+begin_src sh
sonyctl devices                        # list paired Bluetooth devices
sonyctl status                         # model, firmware, noise mode, battery
sonyctl mode                           # print current noise mode
sonyctl battery                        # battery levels (left/right/case)

# noise control (aliases in parentheses)
sonyctl nc                             # noise cancelling (anc, noise-cancelling)
sonyctl ambient                        # ambient sound (transparency, passthrough)
sonyctl ambient --level 12 --voice-focus on
sonyctl off                            # no noise control (normal)
sonyctl mode ambient                   # equivalent to 'sonyctl ambient'

# recovery / power
sonyctl multipoint                     # show multipoint state
sonyctl multipoint reset               # toggle off then on (fix buggy audio state)
sonyctl power-off                      # shut down (no remote power-on exists)

# protocol probing
sonyctl raw 6617 --listen 3            # send raw MDR payload, hex-dump frames
#+end_src

** Machine-readable output

=--json= makes every command print a single JSON object on stdout:

#+begin_src sh
sonyctl --json status
# {"model":"WF-1000XM6","firmware":"1.6.0",
#  "noise":{"mode":"nc","ambient_level":8,"focus_on_voice":false,
#           "adaptive_ambient":false,"adaptive_sensitivity":2},
#  "batteries":[{"part":"left","level_percent":80,"charging":"no"}, ...]}

sonyctl --json mode | jq -r .mode          # -> nc
sonyctl --json battery | jq '.batteries[] | select(.part=="case") | .level_percent'
sonyctl --json raw 6617 --listen 2 | jq -r '.frames[] | .dir + " " + .hex'
#+end_src

Diagnostics never go to stdout — in both modes they are written to stderr, as
plain text normally and as ={"error": "..."}= under =--json=. So stdout stays
parseable even when a command fails, and the exit status tells you what
happened (=0= success, =1= runtime failure, =2= usage error).

** Color

Diagnostics on stderr are printed in gray when stderr is a terminal.
=--color=auto= (the default) detects that; =--color=always= forces the escape
codes on (useful when piping into a pager that interprets them) and
=--color=never= disables them.

Device selection: by default =sonyctl= picks the first paired device whose
name looks like a Sony headphone (=WF-1000XM6= first, then other =WF-=/=WH-=
models). Override with =--device SUBSTR= (name substring) or
=--mac 00:11:22:33:44:55=.

** Notes

- A setting can only be changed by one MDR session at a time; quit Sony's
  Sound Connect app on any phone connected to the same earbuds while testing.
- =multipoint reset= briefly drops the audio link; the next =sonyctl= call may
  need a second or two while the device's control service reappears (the tool
  retries automatically).
- =power-off= is a shutdown, not a restart. The protocol has no power-on or
  reboot command, and a powered-off device cannot receive one — wake the
  earbuds physically (open/close the case, or put them in your ears).

* Bluetooth permission (TCC)

CLI tools inherit the Bluetooth permission of the terminal that launches
them. If connections fail silently, grant your terminal app Bluetooth access
in System Settings → Privacy & Security → Bluetooth.

* Releasing

Releases are cut by pushing a version tag; GitHub Actions
([[file:.github/workflows/release.yml][.github/workflows/release.yml]]) builds
the binaries and publishes them.

1. Bump =project(sonyctl VERSION x.y.z ...)= in =CMakeLists.txt= and commit.
2. =git tag vx.y.z && git push origin master --tags=

The workflow builds arm64, x86_64, and universal binaries on a single
Apple Silicon runner (the Intel slice is cross-compiled), strips them,
generates =SHA256SUMS.txt=, and creates the GitHub Release with generated
notes. Running it via =workflow_dispatch= builds and uploads workflow
artifacts without publishing a release — useful for testing.

=sonyctl version= prints the version compiled into the binary.
